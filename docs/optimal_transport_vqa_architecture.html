End-to-end view

One model, three fusion choices

The pipeline keeps the same image encoder, question encoder, answer embedding, and autoregressive decoder. The selected fusion path changes how image evidence and question meaning are aligned before the decoder sees them.

Target path. Learns question-aware mass distributions, permits unmatched mass through KL relaxation, and produces one fused memory token per valid question token.
Reference OT path. Uses exact row and column marginal constraints. It is useful for verifying solver correctness and for controlled comparisons.
Compatibility path. Reuses stacked attention to compress all evidence into one context token. Version-2 checkpoints load through this path.

Stage 1

English text and image encoders preserve structure

Vision

DeiT spatial tokens

The image processor normalizes an already-scaled image without rescaling it again. DeiT produces two special tokens followed by a regular patch grid. OT receives only the patch tokens, so every visual row in the plan maps to a location in the image.

DeiT(I) = [CLS, DISTILL, v₁ … vₙ]
V = [v₁ … vₙ] ∈ ℝᴮˣᴺˣᴰᵛ
English text

English BERT question tokens

The default encoder is bert-base-uncased. English text receives whitespace normalization, then BERT tokenization. The encoder retains one vector per token. Special and padding tokens remain in the sequence for positional consistency, but their mask excludes them from marginal and transport mass.

q′ = normalize_english_whitespace(q)
Q = BERT(tokenize(q′))
mask = PAD ∨ SPECIAL
Q ∈ ℝᴮˣᴹˣᴰᑫ
English-only text flow. The CLI has no language selector. Training, validation, caching, and prediction use one whitespace normalizer and the English text encoder recorded in the checkpoint. Vietnamese-specific segmenter dependencies and dataset paths have been removed; a Vietnamese encoder name is rejected before model weights load. Compatible English checkpoints map legacy text-module keys onto the generic question encoder and answer embedding names. Why freeze the encoders? The first controlled OT comparison isolates fusion, makes float16 caching valid, reduces compute, and prevents cached features from diverging from online features.
Stage 2

Marginals say where mass begins

A transport plan cannot be interpreted without its source and target mass. Uniform marginals give every valid patch/token equal weight. Question-conditioned marginals learn which patches matter for the question and which question tokens need visual evidence.

Visual marginal a

A masked mean of question tokens creates global question context. For each visual patch, an MLP scores the patch, context, element-wise interaction, and absolute difference.

gQ = masked_mean(Q̄)
sᵛᵢ = MLP([V̄ᵢ,gQ,V̄ᵢ⊙gQ,|V̄ᵢ−gQ|])
a = masked_softmax(sᵛ)

Question marginal b

The symmetric head summarizes the image and scores each question token. Tokens such as “color,” “where,” or an object noun can learn different masses depending on the image.

gV = masked_mean(V̄)
sᑫⱼ = MLP([Q̄ⱼ,gV,Q̄ⱼ⊙gV,|Q̄ⱼ−gV|])
b = masked_softmax(sᑫ)

For each sample, valid entries sum to one before UOT relaxation. Masked entries are set to zero after softmax, avoiding probability leakage into padding.

Stage 3

The ground cost measures patch–token mismatch

Low cost means a visual patch and a question token are compatible. The hybrid formulation combines stable semantic geometry with a trainable pair scorer.

Cᶜᵒˢᵢⱼ = 1 − cosine(V̄ᵢ, Q̄ⱼ)
Cˡᵉᵃʳⁿᵉᵈᵢⱼ = softplus(−MLP([V̄ᵢ,Q̄ⱼ,V̄ᵢ⊙Q̄ⱼ,|V̄ᵢ−Q̄ⱼ|]))
Cᵢⱼ = λ Cᶜᵒˢᵢⱼ + (1−λ) Cˡᵉᵃʳⁿᵉᵈᵢⱼ

Cosine

Bounded, interpretable, and a strong solver reference. It needs no pairwise learned parameters.

Learned

Captures nonlinear correspondence. softplus guarantees a nonnegative cost.

Hybrid

Uses cost_mix to retain semantic geometry while learning task-specific corrections.

Stage 4

Sinkhorn turns cost into soft alignment

The solver works in log space and float32, even under mixed precision. This prevents underflow when exp(−C/ε) becomes very small and keeps invalid patch/token pairs at exactly zero.

log K = −C / ε
log u ← ρᵥ [log a − logsumexp(log K + log v)]
log v ← ρᑫ [log b − logsumexp(log K + log u)]
P = exp(log u + log K + log v)

Balanced OT uses ρᵥ = ρᑫ = 1. UOT uses ρ = τ/(τ+ε), relaxing exact marginal matching through KL penalties. Smaller τ permits more mass to remain unmatched.

Measured stable profile. The original GQA run used ε=0.05, tolerance 1e-4, and 25 iterations. It stopped with residual 0.04402 and 0% convergence. On the same learned costs, ε=0.10, tolerance 1e-3, and a 50-iteration cap reached 100% convergence in about 26 iterations with residual 0.00054. CPU, MPS, and GPU profiles now use these stable numerical settings.

Stage 5

Barycentric projection gathers visual evidence per word

Each question token receives a weighted average of visual patches. The weight comes from one column of the transport plan. Near-zero received mass is clamped before division so the computation remains finite.

mⱼ = Σᵢ Pᵢⱼ
Ṽⱼ = (Σᵢ Pᵢⱼ V̄ᵢ) / max(mⱼ, minimum_mass)
Hⱼ = FusionMLP([Q̄ⱼ, Ṽⱼ, Q̄ⱼ⊙Ṽⱼ, |Q̄ⱼ−Ṽⱼ|])

The result is a sequence of fused tokens rather than one global vector. This gives the decoder access to distinct evidence for different words and preserves the question’s ordering.

Stage 6

The decoder generates the answer autoregressively

Self-attention mask

A causal upper-triangular mask prevents answer position t from seeing future answer tokens. PAD answer IDs are masked as keys.

Cross-attention mask

The question padding mask expands to B×1×Lanswer×M. Every decoder layer uses it, so padded fused-memory tokens cannot affect logits.

training input = [BOS, y₁, y₂, …]
training target = [y₁, y₂, EOS, …]
train loss = CrossEntropy(logits, target, ignore_index=PAD, smoothing=0.1)
validation loss = CrossEntropy(logits, target, ignore_index=PAD)
No reference-answer leakage. At inference the sequence begins with BOS. The model repeatedly chooses the highest-logit next token, appends it, and stops at EOS or the maximum answer length.

Selection and stopping rule

best.pt changes when generated validation F1 improves. If F1 ties, lower unsmoothed validation loss wins. The default patience stops after eight epochs without improvement and is stored in the checkpoint. Teacher-forced training metrics describe optimization only and never select the final model.

Small-data capacity controls

The recommended 1,000-example profile uses d_model=384, two decoder layers, ffn_hidden=1024, dropout 0.2, and frozen pretrained answer embeddings. These settings reduce memorization pressure while retaining trainable answer projection, OT fusion, decoder, and output head.

Compute device

--device auto prefers CUDA, then Apple MPS, then CPU. On Apple Silicon, --device mps makes availability explicit. Checkpoints are staged through CPU to avoid a temporary model-sized duplicate in unified GPU memory.

Logged behavior

Generated EM/F1, unsmoothed validation loss, learning rate, best epoch, patience, unique predictions, top-output fraction, transport cost, entropy, mass, residual, iterations, and convergence rate are recorded. Fresh runs reset metrics.jsonl; resumed runs append.

Answer path

Inference needs only an image and a question

  1. Preprocess the image and question using settings stored with the checkpoint.
  2. Run frozen encoders or load their validated cached token features.
  3. Compute marginals, cost, the OT plan, and fused decoder memory once.
  4. Initialize answer IDs with BOS.
  5. Decode one next token, excluding PAD and BOS from selection.
  6. Keep unfinished rows generating while completed rows receive PAD.
  7. Stop when every row emits EOS or reaches the configured limit.

Performance path

Feature caching removes repeated encoder work

Precompute

DeiT hidden states and contextual question tokens are produced in evaluation mode and stored as float16.

Validate

The manifest records CSV SHA-256, annotation IDs, encoder names/revisions, processor settings, token policy, dtype, and shapes.

Load

Variable question sequences are padded per batch, masks are padded with true, and features cast to the active model dtype.

The loader refuses a cache if the CSV fingerprint or encoder identifier differs. Online and cached data enter the same encode_from_features() interface.

Interpretation and numerical health

What each transport diagnostic means

Transport cost

Σ PᵢⱼCᵢⱼ. Lower means mass uses cheaper alignments; compare only under the same cost scale.

Entropy

−Σ P log P. High values indicate diffuse transport; low values indicate concentrated matches.

Matched mass

ΣP. Balanced OT should be near one. UOT can transport less or slightly more under relaxation.

Unmatched mass

max(1−ΣP,0). Quantifies mass intentionally left without correspondence.

Residual

Balanced marginal error or UOT fixed-point update error. It should fall with stable convergence.

Iterations

Number of Sinkhorn updates before tolerance. Frequent maximum-iteration hits need investigation.

Measured post-training analysis

Why validation stopped improving

The first full GQA UOT run proved that training, generation, checkpointing, and MPS inference work. Its learning curve also revealed that the model memorizes the 1,000-example subset, relies primarily on the question, and truncates every OT solve before convergence.

0.999training F1 · epoch 46
0.21validation F1 · epoch 46
0%OT convergence · old profile

Counterfactual modality test

The diagnostic generated answers normally, with images rotated among samples, and with questions rotated among samples. A modality that controls the prediction should cause frequent changes when shuffled.

Image shuffled
31.25%
Question shuffled
84.38%
Interpretation. Shuffled-image F1 was 0.28125 versus original F1 0.25 on 32 examples. The small increase is sampling noise, not useful behavior. The low change rate and large question-shuffle response show question-prior dominance and weak visual grounding.

Capacity

The checkpoint exposes 86.5M trainable parameters for 1,000 examples. The regularized profile uses a 384-wide, two-layer decoder, 1024-wide feed-forward blocks, dropout 0.2, and frozen answer embeddings.

Output collapse

Only eight distinct answers appeared in the 32-example panel. The most frequent answer occupied 31.25% of outputs, and late-run F1 approached the 0.19 “yes” majority baseline.

Coverage

The training split contains 245 unique answers; validation contains 50. Nineteen percent of validation examples use an answer never observed in training, limiting exact-match performance.
