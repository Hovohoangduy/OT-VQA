End-to-End View

Five Multimodal Fusion Families · Three Transport Paradigms

The OT-VQA architecture unifies diverse multimodal fusion mechanisms under a single mathematical and engineering contract. All variants share the same frozen image encoder, question encoder, answer embeddings, and autoregressive Transformer decoder.

OT-SAN (uot_san / balanced_ot_san): Adds masked stacked attention over OT-fused tokens. Starting from their masked mean, it uses a learnable gate initialized to sigmoid(-2.0) ≈ 0.12 to scale only the attention-derived correction, then prepends the resulting summary to the local tokens [S, H].
BAN with OT (uot_ban / balanced_ot_ban): Computes multiple bilinear attention glimpses across visual patches and words. The OT transport plan acts as an additive log-prior score_g + λ_ot * log(P + ε) with a learned scalar λ_ot initialized to 1.0.
MUTAN with OT (uot_mutan / balanced_ot_mutan): Employs low-rank Tucker bilinear tensor decomposition (rank=5). In the OT variant, native pooling is replaced with normalized OT columns Ṽ_j = Σ_i P_ij V_i / max(Σ_i P_ij, ε), isolating tensor fusion on OT-aligned evidence.
Cross-Attention with OT (uot_cross_attention): Multi-head cross-attention where questions query visual keys/values. The normalized log-transport plan is added directly into attention logits across all heads: QK^T / sqrt(d) + λ_ot * log(P^T + ε).
Q-Former with OT (uot_qformer): A lightweight Querying Transformer with 8 learned query tokens. In the non-OT variant, queries attend [V, Q]; in the OT variant, queries attend [V, H_ot] where H_ot is grounded barycentric tokens.
Barycentric Baseline (uot / balanced_ot): Standard OT alignment baseline. Directly projects pooled visual patches through a 4-way interaction MLP [Q̄, Ṽ, Q̄⊙Ṽ, |Q̄−Ṽ|] to create word-level memory tokens.
Legacy SAN (san): Historical non-OT baseline. Compresses the entire visual scene and question into a single summary token [B, 1, d_model] via 2-layer stacked attention. Version-2 checkpoints remain strictly loadable.

Stage 1

Pretrained Visual & Linguistic Encoders

Default Vision Encoder

ViT-Base Patch16 (ImageNet-21k)

Default: google/vit-base-patch16-224-in21k. Produces 1 CLS token followed by 196 spatial patch tokens. The CLS token is discarded so that every row in the visual token tensor maps strictly to a physical spatial location in the 14×14 grid.

ViT(I) = [CLS, v₁ … v₁₉₆]
V = [v₁ … v₁₉₆] ∈ ℝᴮˣ¹⁹⁶ˣ⁷⁶⁸
Text Encoder

English BERT-Base Uncased

Default: bert-base-uncased. English questions receive whitespace normalization and subword tokenization. Special boundary tokens ([CLS], [SEP]) and padding tokens are retained for positional consistency but are strictly masked out of transport mass.

q′ = normalize_english_whitespace(q)
Q = BERT(tokenize(q′))
mask = PAD ∨ SPECIAL
Q ∈ ℝᴮˣᴹˣ⁷⁶⁸

Why freeze encoders? Freezing ViT and BERT enables float16 feature caching, speeds up training by 4-5x, prevents catastrophic forgetting on small datasets, and strictly isolates the multimodal fusion comparison.

Question-Conditioned Marginals (ConditionalMarginal)

Optimal Transport aligns probability measures. Uniform marginals waste transport mass on background clutter; question-conditioned marginals dynamically predict where importance lies before transport begins.

Visual Marginal a

A masked average of question tokens provides global semantic intent. A multi-feature MLP scores each visual patch against this context:

gQ = masked_mean(Q̄)
sᵛᵢ = MLP([V̄ᵢ, gQ, V̄ᵢ⊙gQ, |V̄ᵢ−gQ|])
a = masked_softmax(sᵛ) ∈ ℝᴮˣ¹⁹⁶

Question Marginal b

Symmetrically, the image is pooled into a global scene descriptor, and an MLP predicts which question tokens require visual evidence:

gV = masked_mean(V̄)
sᑫⱼ = MLP([Q̄ⱼ, gV, Q̄ⱼ⊙gV, |Q̄ⱼ−gV|])
b = masked_softmax(sᑫ) ∈ ℝᴮˣᴹ

The 4-Way Interaction Operator in Code

In model/optimal_transport.py, both marginal heads expand the context vector and construct a 4-way concatenation of dimension 4 × ot_dim:

# From model/optimal_transport.py (ConditionalMarginal.forward) expanded = context.unsqueeze(1).expand_as(tokens) features = torch.cat([ tokens, # 1. Base token representation [B, L, ot_dim] expanded, # 2. Global query/scene context [B, L, ot_dim] tokens * expanded, # 3. Multiplicative gating (co-occurrence) (tokens - expanded).abs() # 4. Absolute difference (feature discrepancy) ], dim=-1) return masked_softmax(self.scorer(features).squeeze(-1), padding_mask)

Padding Mask Isolation Guarantee

The helper masked_softmax() ensures probability mass is strictly conserved over valid tokens and strictly zero over padding:

def masked_softmax(logits: torch.Tensor, padding_mask: torch.Tensor) -> torch.Tensor: masked = logits.float().masked_fill(padding_mask, float("-inf")) return torch.softmax(masked, dim=-1).to(logits.dtype).masked_fill(padding_mask, 0.0)

By filling padded positions with -inf before softmax, e−∞ = 0, guaranteeing that valid.sum() == 1.0 with zero probability mass leakage into padding.

Hybrid Ground Cost Matrix (PairwiseCost)

The ground cost Cij quantifies the semantic incompatibility between visual patch i and question word j. Transporting mass between incompatible pairs incurs a penalty. A hybrid formulation blends geometric cosine stability with a trainable nonlinear neural distance.

Ccosij = 1 − cosine(V̄i, Q̄j)
Clearnedij = softplus(−MLP([V̄i, Q̄j, V̄i⊙Q̄j, |V̄i−Q̄j|]))
Cij = λ · Ccosij + (1−λ) · Clearnedij ∈ ℝᴮˣ¹⁹⁶ˣᴹ

Cosine Semantic Metric

Cosine distance 1 − cos(V̄i, Q̄j) is bounded in [0, 2], parameter-free, and provides a stable geometrical anchor that prevents Sinkhorn divergence early in training.

Learned Pairwise MLP

Captures nonlinear multimodal correspondence. Using softplus(-score) guarantees strict nonnegativity (C ≥ 0) without gradient clipping or dead neurons.

Convex Mixture Parameter λ

Configured via cost_mix (default 0.5), smoothly balancing pre-aligned geometric prior with learned task-specific corrections.

PyTorch Implementation in model/optimal_transport.py

# From model/optimal_transport.py (PairwiseCost.forward) visual_unit = F.normalize(visual.float(), dim=-1) question_unit = F.normalize(question.float(), dim=-1) semantic = 1.0 - torch.matmul(visual_unit, question_unit.transpose(1, 2)) visual_pairs = visual.unsqueeze(2).expand(-1, -1, question.size(1), -1) question_pairs = question.unsqueeze(1).expand(-1, visual.size(1), -1, -1) pair_features = torch.cat([ visual_pairs, question_pairs, visual_pairs * question_pairs, (visual_pairs - question_pairs).abs() ], dim=-1) learned = F.softplus(-self.learned(pair_features).squeeze(-1).float()) return (config.cost_mix * semantic + (1.0 - config.cost_mix) * learned).to(visual.dtype)
Stage 4 · Source Code Deep Dive

Log-Domain Sinkhorn Solver (sinkhorn_transport)

Entropy-regularized Optimal Transport solves for the soft correspondence matrix P. The repository implements a differentiable, batched, log-domain Sinkhorn solver supporting both exact Balanced OT and KL-relaxed Unbalanced OT (UOT).

Mathematical Formulation

The primal optimization problem for entropy-regularized Unbalanced Optimal Transport is:

min_{P ≥ 0} ⟨P, C⟩ − ε·H(P) + τᵥ·KL(P·1ₘ || a) + τᵩ·KL(Pᵀ·1ₙ || b)
where H(P) = −Σᵢⱼ Pᵢⱼ(log Pᵢⱼ − 1) is Shannon entropy,
KL(u || a) = Σᵢ (uᵢ log(uᵢ / aᵢ) − uᵢ + aᵢ) relaxes exact marginal matching.

When relaxation parameters τv, τq → ∞, the KL penalties force strict marginal conservation P1 = a and PT1 = b, reducing to classical Balanced OT.

Dual Variables & Relaxed Exponents in Code

The optimal plan is parameterized by dual scaling vectors u ∈ ℝN and v ∈ ℝM through the Gibbs kernel K = exp(−C / ε):

Pᵢⱼ = uᵢ · Kᵢⱼ · vⱼ = exp(log uᵢ − Cᵢⱼ/ε + log vⱼ)
Balanced OT: visual_power = 1.0, question_power = 1.0
Unbalanced OT: visual_power = τᵥ / (τᵥ + ε), question_power = τᵩ / (τᵩ + ε)

Differentiable Log-Domain Iterations in PyTorch

# From model/optimal_transport.py (sinkhorn_transport) # Solver executes strictly in float32 to prevent underflow under mixed precision cost32 = cost.float() a = visual_marginal.float().clamp_min(config.minimum_mass) b = question_marginal.float().clamp_min(config.minimum_mass) log_kernel = (-cost32 / config.epsilon).masked_fill(~pair_valid, float("-inf")) for step in range(1, config.max_iterations + 1): old_u, old_v = log_u, log_v # Dual update for visual potentials (row scaling) visual_lse = torch.logsumexp(visual_update_kernel + log_v.unsqueeze(1), dim=2) log_u = visual_power * (log_a - visual_lse).masked_fill(~valid_visual, 0.0) # Dual update for question potentials (column scaling) question_lse = torch.logsumexp(question_update_kernel + log_u.unsqueeze(2), dim=1) log_v = question_power * (log_b - question_lse).masked_fill(~valid_question, 0.0) # Stopping criterion: maximum potential variation delta_u = (log_u - old_u).abs().masked_fill(~valid_visual, 0.0).amax(1) delta_v = (log_v - old_v).abs().masked_fill(~valid_question, 0.0).amax(1) residual = torch.maximum(delta_u, delta_v) if residual.le(config.tolerance).all(): break # Reconstruct transport plan: P = exp(log u + log K + log v) log_plan = log_u.unsqueeze(2) + log_kernel + log_v.unsqueeze(1) plan = torch.exp(log_plan).masked_fill(~pair_valid, 0.0)

Barycentric Projection & Token Fusion (OptimalTransportFusion)

How does the 2D transport matrix P become a sequence of multimodal tokens for the decoder? The transport plan columns act as interpolation weights that project visual patch tokens into question space, creating a visual barycenter for each word.

Received Mass per Word

Summing down column j of the plan yields the total transported mass received by question word j:

mⱼ = Σᵢ₌₁¹⁹⁶ Pᵢⱼ ∈ [0, 1]

In UOT, non-visual words (e.g. "what", "is") receive near-zero mass, while visual entities (e.g. "color", "dog") receive high mass.

Normalized Visual Evidence Barycenter

Each question word receives a weighted centroid of visual patches, normalized by its received mass:

Ṽⱼ = (Σᵢ₌₁¹⁹⁶ Pᵢⱼ V̄ᵢ) / max(mⱼ, minimum_mass) ∈ ℝᵈᵒᵗ

Clamping by minimum_mass=1e-8 prevents division by zero when a word receives negligible transported mass.

Barycentric Fusion MLP in model/optimal_transport.py

# From model/optimal_transport.py (OptimalTransportFusion.forward) received_mass = plan.sum(1) # [B, M] visual_evidence = torch.bmm(plan.transpose(1, 2), visual.float()) # [B, M, ot_dim] visual_evidence = visual_evidence / received_mass.unsqueeze(-1).clamp_min(self.config.minimum_mass) visual_evidence = visual_evidence.to(question.dtype) # 4-way fusion into model dimension d_model fusion_features = torch.cat([ question, visual_evidence, question * visual_evidence, (question - visual_evidence).abs() ], dim=-1) fused_tokens = self.fusion(fusion_features).masked_fill( question_padding_mask.unsqueeze(-1), 0.0 )

The resulting tensor H ∈ ℝB × M × dmodel preserves the sequence length and word order of the original question, with each word enriched by its aligned visual context.

OT-SAN: Gated Global Summary Over Local Alignments (OTSAN)

Pure OT token fusion preserves local word alignments but lacks a single global scene summary; legacy SAN compresses everything into one vector and destroys token order. OT-SAN bridges this gap.

Architecture

Masked Stacked Attention + Learnable Gate

OT-SAN takes the local barycentric question tokens H and runs 1 or 2 masked attention layers. Let S0 be their masked mean and Sattn the context after attention updates. A learnable gate initialized to gate_init = -2.0 controls the correction away from the stable mean:

S₀ = masked_mean(H)
S_attn = StackedAttention(H, context=S₀)
g = σ(gate_logit)
S = dropout(S₀ + g · (S_attn − S₀))
Memory = [S, H] ∈ ℝᴮˣ⁽¹⁺ᴹ⁾ˣᵈᵐᵒᵈᵉˡ
Decoder Advantage

Rich Context for Decoder

The decoder receives both the gated global summary S (position 0) and the token-aligned evidence H (positions 1 … M). Cross-attention heads can attend either to the global scene state or to specific question words as needed.

CLI: --fusion uot_san \
--ot_san_layers 1 \
--ot_san_hidden_dim 128 \
--ot_san_gate_init -2.0

PyTorch Implementation in model/ot_san.py

# From model/ot_san.py (OTSAN.forward) initial_context = masked_mean(fused_tokens, padding_mask) context = initial_context for layer in self.layers: context, weights = layer(fused_tokens, context, padding_mask) gate = torch.sigmoid(self.gate_logit) summary = self.summary_dropout( initial_context + gate * (context - initial_context) ) memory = torch.cat([summary.unsqueeze(1), fused_tokens], dim=1)
Important implementation detail: the gate scales only the attention-derived correction context − initial_context; it does not scale the complete summary token. At initialization, sigmoid(−2) ≈ 0.119, so the module begins close to a stable masked-mean summary and gradually learns how much stacked-attention refinement to add.
Stage 7 · Source Code Deep Dive

Five Multimodal Fusion Families & OT Augmentation

This section follows the active implementations in model/vqa_model.py, model/sans.py, model/ot_san.py, and model/fusion_methods.py. The native SAN has its own legacy path; OT-SAN consumes barycentric tokens; BAN, MUTAN, cross-attention, and Q-Former share the FusionInput/FusionOutput interface.

SAN

Stacked Attention

Without OT: BERT embeddings pass through the question encoder's LSTM to form one context vector. Each StackAttention layer scores projected image tokens using that context, adds the attended image vector back to it, and finally emits one decoder-memory token.
With OT: this legacy SAN path is frozen. OTSAN instead refines the masked mean of OT-fused word tokens and prepends the gated summary, producing [summary, H_ot].

BAN

Bilinear Attention

Without OT: Projected patch and word features form G=2 bilinear score maps. Each glimpse pools a visual context per word and applies a residual update LN(memory + joint(context ⊙ memory)).
With OT: row-normalized Pᵀ becomes an additive log-prior shared across glimpses, scaled by the learnable ot_prior_scale.

MUTAN

Multimodal Tucker

Without OT: scaled dot-product question-to-image attention produces one visual evidence vector per word.
With OT: normalized columns of P replace those attention weights. Both paths then create rank-5, 256-dimensional visual/question factors, multiply them elementwise, sum over rank, project, and add a residual question connection with layer normalization.

Cross-Attention

Transformer Fusion

Without OT: a configurable stack (default one layer, four heads) uses word tokens as queries and image patches as keys/values, followed by residual output projection, feed-forward network, and two layer norms.
With OT: normalized log(Pᵀ) is broadcast to every head and added to logits using learnable ot_prior_scale.

Q-Former

Querying Transformer

Without OT: eight learned queries pass through two layers of self-attention, cross-attention to [project(V), project(Q)], and an FFN.
With OT: raw question memory is replaced with a learned projection of transport.fused_tokens, so queries attend [project(V), project(H_ot)]. The decoder receives exactly eight unmasked query tokens.

How Each Method Works, Step by Step

SAN / OT-SAN — compress globally, with an optional local-token escape route

  1. Native SAN forms a question state. The token sequence is reduced by the question encoder LSTM to one vector q.
  2. Each attention layer scores every image location. It computes tanh(Wv·Vᵢ + Wq·q), maps this to one scalar per patch, and applies softmax across patches.
  3. The attended visual vector updates the question. The weighted patch sum is added to q; later SAN layers repeat this with the already visually enriched state.
  4. The decoder receives one token. This is efficient and forces a strong global bottleneck, but token order and local word-specific alignments are no longer directly available.
  5. OT-SAN changes the input representation. OT first creates grounded word tokens H. Their masked mean is refined through one or two masked attention layers, while the gate controls only the refinement. The decoder receives both the summary and every grounded word token.
Characteristic combination: additive recurrent visual evidence. Native SAN combines “where to look” and “what the question means” into a single evolving vector; OT-SAN combines a global summary with an intact local token sequence.

Best suited to: questions that can be answered from one dominant region or a compact scene summary.

Main risk: native SAN's one-token bottleneck may discard relations between multiple words or objects. OT-SAN is richer but introduces more capacity and possible overfitting.

BAN — combine every word–patch pair through several attention glimpses

  1. Visual and question tokens are projected to d_model, then separately transformed to a 256-dimensional attention space with tanh.
  2. For each of two default glimpse vectors, an einsum produces a complete [word, patch] score matrix. Unlike ordinary dot-product attention, each glimpse owns a learned direction in the shared bilinear feature space.
  3. When OT is enabled, each word's transport weights over patches are normalized, logged, multiplied by ot_prior_scale, and added to every glimpse. The learned BAN score can still disagree with OT.
  4. Softmax over patches creates a visual context for every word and glimpse. Glimpses are then applied sequentially: memory ← LN(memory + joint(context_g ⊙ memory)).
Characteristic combination: multiplicative word–region interaction repeated across complementary glimpses. OT acts as a soft Bayesian-style prior, not a replacement for BAN attention.

Best suited to: answers requiring several complementary visual cues or object–attribute combinations.

Main risk: all glimpses share the same OT prior; a strongly scaled inaccurate plan can reduce glimpse diversity.

MUTAN — factorized tensor interaction after selecting visual evidence

  1. Each question word selects a visual evidence vector. The native path uses scaled dot-product attention; the OT path directly uses normalized Pᵀ.
  2. The selected visual vector and corresponding question vector are independently expanded into rank × factor_dim tensors (defaults: 5 × 256).
  3. Matching visual and question factors are multiplied elementwise. Summing the five rank slices approximates a much larger bilinear tensor without materializing it.
  4. The 256-dimensional fused factor is projected to d_model, added back to the question token, layer-normalized, and masked.
Characteristic combination: explicit multiplicative feature chemistry. Pooling decides which patch evidence belongs to each word; Tucker factors decide which visual and linguistic channels interact.

Best suited to: fine-grained attribute and relation interactions where additive fusion is insufficient.

Main risk: OT replaces native pooling completely. If the plan is wrong—especially under strict Balanced OT—the factorization cannot recover excluded visual evidence.

Cross-attention — learn alignment directly, optionally regularized by OT

  1. Question tokens become queries; image patches become keys and values. Each of four heads operates in its own subspace.
  2. Every head computes QKᵀ/√head_dim. If OT exists, normalized log(Pᵀ) is broadcast across heads and added before visual masking and softmax.
  3. The weighted values are concatenated, projected, dropped out, and added residually to the question tokens before layer normalization.
  4. A position-wise feed-forward network supplies nonlinear channel mixing, followed by a second residual connection and layer norm. Padded word positions are zeroed.
Characteristic combination: flexible content-based retrieval. Unlike BAN, each head learns its own query/key projections; unlike MUTAN, visual selection and feature transformation are learned jointly.

Best suited to: general token-level grounding where multiple relation types benefit from separate heads.

Main risk: cross-attention already learns alignment. Adding the same OT prior to every head can over-constrain otherwise useful alternative alignments—consistent with the measured decrease in this benchmark.

Q-Former — query a long multimodal sequence through a fixed eight-token bottleneck

  1. Eight learned query vectors are expanded across the batch. They are parameters, not derived directly from a particular question.
  2. Self-attention lets queries specialize cooperatively—for example, different queries can capture objects, attributes, or relations.
  3. Queries cross-attend the concatenated multimodal memory. The native path uses projected raw question tokens; the OT path substitutes projected grounded barycentric tokens. Visual patch tokens remain present in both paths.
  4. An FFN refines each query. Two default layers repeat self-attention, cross-attention, and FFN. The resulting eight tokens become the complete decoder memory with no padding positions.
Characteristic combination: learned information bottleneck. OT does not bias Q-Former attention weights directly; it improves the memory that the queries inspect.

Best suited to: compressing long image–question sequences into a predictable memory size for the decoder.

Main risk: eight queries may under-represent complex scenes, while extra Q-Former layers can overfit a small dataset. Its gain from UOT suggests grounded memory helps the bottleneck decide what to retain.

2. BAN: bilinear glimpses plus an optional transport prior:
scores = einsum("bnh,bmh,gh->bgmn", visual_hidden, question_hidden, glimpse_vectors) if inputs.transport is not None: prior = inputs.transport.plan.transpose(1, 2).float() prior = prior / prior.sum(-1, keepdim=True).clamp_min(1e-8) scores = scores + self.ot_prior_scale * prior.clamp_min(1e-8).log().unsqueeze(1) contexts = einsum("bgmn,bnd->bgmd", softmax(scores), visual)
3. MUTAN: attention/OT pooling followed by low-rank fusion:
weights = native_dot_product_attention if transport is None \ else row_normalize(transport.plan.transpose(1, 2)) evidence = torch.bmm(weights, visual) v = self.visual_factor(evidence).reshape(B, M, rank, factor_dim) q = self.question_factor(question).reshape(B, M, rank, factor_dim) fused = (self.dropout(v) * self.dropout(q)).sum(dim=2) memory = self.norm(question + self.output(fused))
4. Cross-attention: the same OT log-prior is reused by every layer:
prior = row_normalize(transport.plan.transpose(1, 2)).clamp_min(1e-8).log() scores = torch.matmul(q, k.transpose(-1, -2)) / math.sqrt(head_dim) scores = scores + self.ot_prior_scale * prior.unsqueeze(1) question = norm1(question + dropout(output(softmax(scores) @ v))) question = norm2(question + dropout(ffn(question)))
5. Q-Former: OT changes the question-side memory, not its attention logits:
if inputs.transport is not None: question_memory = self.ot_grounded_projection(inputs.transport.fused_tokens) else: question_memory = self.question_projection(inputs.question_tokens) memory = torch.cat([self.visual_projection(inputs.visual_tokens), question_memory], dim=1) queries = self.query_tokens.unsqueeze(0).expand(B, -1, -1) for layer in self.layers: queries, weights = layer(queries, memory, memory_mask)
Masking, memory, and optimization behavior: all token methods validate Boolean masks and require at least one valid visual and question token. Padded question positions are zeroed after fusion. BAN, MUTAN, and cross-attention emit one memory token per question position; Q-Former emits eight unmasked query tokens; native SAN emits one unmasked token; OT-SAN emits one unmasked summary followed by masked OT word tokens. For non-SAN models, the BERT encoder, legacy LSTM, image projection, and legacy SAN stack are frozen. In non-OT BAN/cross-attention, ot_prior_scale is also frozen; Q-Former trains either its raw-question projection or its OT-grounded projection, never both.
Stage 8

Autoregressive Transformer Decoder

Causal Self-Attention Mask

An upper-triangular Boolean mask prevents target token t from attending to future tokens t+1 … L. Answer PAD tokens are masked as keys.

mask[i, j] = True if j > i or pad[j]

Fused-Memory Cross-Attention Mask

The memory padding mask expands to B × 1 × L_answer × L_memory. Padded fused tokens cannot influence decoder hidden states.

memory_mask[b, 1, t, m] = memory_padding[b, m]

training target = [y₁, y₂, EOS, …]

Why the results differ by fusion family

OT is an inductive bias

BAN and Q-Former benefit most because OT supplies explicit patch-to-word structure where their native bottlenecks otherwise must discover it from only 1,000 training examples.

UOT tolerates irrelevant tokens

Questions contain non-visual words and images contain clutter. UOT may leave mass unmatched; Balanced OT must allocate all mass, which can create noisy correspondences. This is consistent with UOT outperforming Balanced OT in SAN, MUTAN, cross-attention, and Q-Former.

Strong attention can be over-biased

Cross-attention already learns a dense alignment. Adding λ_ot log(P) can double-impose an alignment and suppress alternatives, matching its observed 3.6–4.2 point F1 decline.

Generalization warning: OT variants usually show much larger train–validation gaps. For example, cross-attention UOT has a gap of 0.4349 versus 0.2270 without OT, and BAN UOT has 0.3502 versus −0.0166. The added alignment module and roughly 1.0–1.6M extra trainable parameters can fit the small training set without reliably improving validation answers.

Why Can OT Perform Worse Than the Same Method Without OT?

The transport solver is numerically valid, but a valid transport plan is not automatically the best alignment for answer generation. OT introduces an additional structural assumption: that useful reasoning can be represented as low-cost mass transported between image patches and question words. When that assumption, its learned cost, or its optimization signal is imperfect, OT can restrict a fusion module that would otherwise learn a better task-specific alignment.

1. Balanced OT must explain every patch and every word

Balanced Sinkhorn enforces row and column marginals: all prescribed visual mass and question mass must participate. Real VQA inputs violate this idealized one-to-one accounting. Many of the 196 ViT patches are background, and words such as “what”, “is”, or “the” may carry little visual grounding information.

Consequently, Balanced OT can assign nonzero mass to irrelevant word–patch pairs merely to satisfy its marginals. That noisy mass then enters BAN and cross-attention as a log-prior and completely replaces native visual pooling in MUTAN.

Evidence: Balanced OT lowers F1 for SAN (−0.0060), MUTAN (−0.0283), and cross-attention (−0.0417), and its five-method mean falls from 0.3669 to 0.3639. UOT, which relaxes marginal conservation, beats Balanced OT in four of five families.

2. The OT objective is indirect: it optimizes alignment cost, not answer F1

The plan is generated from a hybrid cosine/learned pairwise cost and question-conditioned marginals. These components are trained through the answer loss, but there is no direct supervision saying which word should align with which patch. On only 1,000 training examples, the cost network can discover a transport pattern that helps minimize training cross-entropy without representing the causal evidence needed on unseen questions.

Moreover, low transport cost only means that the projected features look compatible under the current cost function. It does not guarantee that the aligned feature is discriminative between candidate answers.

Observable symptom: OT models often achieve high training F1 while validation F1 stagnates. Cross-attention UOT reaches training F1 0.8102 at its selected epoch but validation F1 only 0.3753, producing the largest reported gap, 0.4349.

3. OT can duplicate or override a fusion method’s own attention

Cross-attention: already learns multi-head word-to-patch alignment from QKᵀ. Adding the same log(Pᵀ) bias to every head pushes all heads toward one external alignment and can suppress useful head diversity. This is the clearest negative result: no OT scores 0.4110, Balanced OT 0.3693, and UOT 0.3753.

MUTAN: OT does not merely regularize native attention; it replaces the native dot-product pooling weights. If the transport plan misses a relevant patch, the later Tucker factors never see that evidence. Balanced MUTAN loses 0.0283 F1.

BAN: OT is softer: it is added as a learned-scale prior while BAN retains its own bilinear scores. This lets BAN use the prior when helpful and counteract it when not, which plausibly explains why both OT variants improve BAN.

Design principle: OT is safer when injected as an optional, learnably weighted prior than when it replaces native evidence selection or biases every attention head identically.

4. Added capacity increases overfitting on the small training split

The OT subsystem adds projections, two conditional marginal networks, a learned pairwise-cost MLP, and a four-way fusion projection—approximately 1.0–1.6 million trainable parameters depending on the family. It also creates an easier route for the model to memorize dataset-specific word–region correlations.

The train–validation gap rises sharply for many OT configurations: BAN moves from −0.0166 without OT to 0.3364/0.3502 with Balanced/UOT; Q-Former moves from 0.0204 to 0.2577/0.1481. Higher training fit is therefore not evidence that transport improves grounding.

Practical implication: stronger dropout, weight decay, freezing parts of the OT cost/marginal networks, or training on substantially more data may be necessary before the added alignment capacity generalizes.

5. Autoregressive F1 amplifies small representation errors

Checkpoint quality is measured from generated answers, whereas optimization uses teacher-forced token cross-entropy. A slightly distorted fused memory may still assign reasonable probability to the correct next token when the true prefix is supplied, yet choose a wrong early token during free generation. That error changes the later prefix and can alter the complete answer.

This is why loss and F1 sometimes disagree. MUTAN UOT has slightly higher F1 than no-OT MUTAN (0.3890 versus 0.3870) despite much worse validation loss (1.8896 versus 1.5095). The metrics observe different behavior.

Interpretation rule: use generated F1 for model selection, but inspect validation loss, output diversity, and modality-shuffle diagnostics to determine whether an apparent F1 change reflects better grounding, calibration, or a small decoding effect.
Bottom line: the current experiment does not show that “OT is worse” in general. It shows that OT is method-dependent. UOT improves the five-family mean and helps SAN, BAN, and Q-Former, is effectively neutral for MUTAN, and harms cross-attention. Balanced OT is less robust because strict mass conservation is poorly matched to images with clutter and questions containing non-visual words. Because every comparison uses only seed 42, these mechanisms are evidence-supported hypotheses—not proven causal conclusions.

Autoregressive Prediction Pipeline

  1. Preprocess image via ViT processor and question via BERT tokenizer.
  2. Extract spatial patch tokens V and question tokens Q.
  3. Compute optimal transport plan P (if OT variant enabled).
  4. Execute multimodal fusion module to produce contextual memory H.
  5. Initialize answer sequence with [BOS].
  6. Autoregressively predict next token logit via greedy argmax, appending each token to sequence.
  7. Stop when [EOS] is produced or max_len (default 12) is reached.
