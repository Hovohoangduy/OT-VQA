01 / The implemented system

Optimal transport is the fusion layer

Given an image and an English question, VQAModel extracts spatial image features and contextual question features. With fusion='ot', PartialTransportFusion solves a differentiable matching problem between them. The matching determines which visual evidence enriches each question token.

REPRESENT

Keep local information

Preserve spatial image locations and individual question tokens instead of reducing both inputs to a single vector before fusion.

ALIGN

Allocate shared mass

Use one transport plan with prescribed row and column mass. Two dustbins give local content an alternative to matching directly.

GENERATE

Read grounded memory

A causal answer decoder reads one global memory token plus visually enriched question tokens and predicts the next answer token.

What is learned?

The question encoder, feature projections, memory construction, decoder, and vocabulary head learn from answer-token cross-entropy. The OT solver has no learnable weights of its own; gradients flow through its finite sequence of operations into the costs and features.

This guide describes the checked-in OT implementation and its supporting pipeline. Other fusion implementations are outside the architecture walkthrough. The interactive example uses synthetic costs and is not a trained-model prediction.

Reading path for writing a paper

Read Sections 2–7 for the architecture, then formal methodology, derivations, and the algorithm. Use experiment design to plan evidence and manuscript material to draft the paper. Mathematical properties below are derived from this implementation; proposed experiments are explicitly labeled and no benchmark results are invented.

02 / Full pipeline and model architecture

From dataset preparation to a generated answer

The complete process has three connected parts: prepare the data and initialize the OT model; train and select a checkpoint; then load that checkpoint for held-out evaluation or single-example inference. The model-level diagram below expands the encoding and decoding operation used within this lifecycle.

Reference answers enter teacher forcing and scoring, while the transport plan is computed from the image and question. Final evaluation uses the selected checkpoint; single-example inference needs no reference answer.

Model forward pass inside the pipeline

Stage 3’s encoder/OT/decoder chain, Stage 4’s evaluation batches, and Stage 7’s inference all use the following architecture. During training, the answer prefix is taken from the reference; during greedy generation, it is built from the model’s previous predictions.

Figure 1B · Model computation within the full pipeline. Read the top two branches into the OT chain, then the answer prefix into the decoder. OT constructs the memory; the decoder subsequently attends to that memory.

VQAModel.encode() runs the image and question branches once per batch. decode() reads their memory alongside answer IDs. Training supplies the reference prefix; generation builds the prefix one token at a time.

TRAINING BATCH

Forward → loss → parameter update

image + question → encoders → partial OT → memory; reference answer → prefix embeddings → decoder → logits; shifted targets → cross-entropy → backward → AdamW. Each subsequent batch recomputes the OT plan using the updated trainable representations.

INFERENCE LOOP

One encoding → repeated answer decoding

image + question → partial OT memory once; [BOS] → decode prefix → last-position logits → forbid PAD/BOS → argmax → append. Repeat until every sample emits EOS or the configured length limit is reached, then decode IDs to strings.

What is reused, and what is recomputed?

The image/question memory and transport plan are reused within one generation sequence. The whole growing answer prefix is decoded again at each step; there is no decoder KV cache. New training/evaluation batches recompute encodings and transport. A checkpoint persists weights and configuration, not a reusable plan for every future image/question pair.

For a paper, Figure 1A explains the experiment lifecycle and Figure 1B explains the network architecture. Use the stage table to connect each diagram to source code, and Algorithm 1 for the detailed OT memory operation.

03 / Components surrounding OT

What each component contributes

DATA CONTRACT

CSV processing & dataset

load_dataframe() checks required columns and normalizes whitespace. VQADataset opens images as RGB and returns (anno_id, image, question, answer). A missing anno_id is generated. Training and scored evaluation require answers.

FROZEN

ImageEmbedding

The default backbone is apple/mobilevitv2-2.0-imagenet1k-256. Spatial maps flatten from [B,C,Hf,Wf] to [B,K,C]. The image processor applies the configured channel order and normalization. Backbone weights stay frozen, in evaluation mode, under torch.no_grad().

TRAINABLE

QuestionEmbedding

The default is sentence-transformers/all-MiniLM-L12-v2. The tokenizer pads to the batch length and truncates to the question limit. Contextual token states go to OT. Padding and special tokens are excluded from local matching; punctuation and subword pieces remain content tokens unless marked special.

GLOBAL CONTEXT

Question & image summaries

For names beginning sentence-transformers/, the question summary is the normalized mean over attention-mask-valid states, including special tokens. Other supported text paths use the first token state. The image summary is the mean of projected spatial tokens. Both influence dustbin costs and global memory.

TRAINABLE

Feature & fusion projections

image_projection maps the image width to D, or is identity when widths match. Inside OT, question_projection always maps text width to D. grounding_projection transforms aligned visual evidence, while global_projection combines the two global summaries.

FROZEN BY CLI DEFAULT

AnswerEmbedding

A separate pretrained embedding module from the same text model embeds answer IDs, including their positions. It does not run the full question encoder. answer_projection maps its width to D when needed. CLI training freezes the embedding weights; direct VQAModel() construction leaves them trainable by default.

Shared answer decoder, used by the OT model

Decoder stacks layers containing causal answer self-attention, cross-attention to OT memory, and a two-layer feed-forward network with ReLU. Each sublayer uses dropout, a residual connection, and post-residual normalization. Attention has learned query/key/value projections and scales dot products by the square root of the per-head width.

The output head is Dropout(0.3) → Linear(D,D) → GELU → Linear(D,V). Its final vocabulary size comes from the answer embedding table. The head is a separate learned projection; it is not tied to the embedding weights.

Cross-attention inside the decoder is part of the OT pipeline.

It reads already-fused memory. The transport plan itself is used earlier to construct that memory and is not passed directly to decoder attention.

05 / The core method

Partial local matching through balanced extended OT

1. Project values, then normalize copies for cost

Let xᵢ be projected spatial image values and qⱼ = Wq · textⱼ + bq be projected question values. Their unnormalized versions are retained as memory values. FP32, L2-normalized copies define cosine distance:

Cᵢⱼ = 1 − cosine(xᵢ, qⱼ) gᵢ = meanᵢ(xᵢ) gq = question_projection(question_global)

In the integrated model, question_global comes from the encoder. If fusion is called directly without it, the fusion module computes the masked mean of the projected valid question tokens.

2. Add two dustbins

The four blocks of the extended cost matrix.
Source → destinationQuestion tokensQuestion dustbin
Image locations1 − cosine(xᵢ, qⱼ)

Image dustbin1 − cosine(gᵢ, qⱼ)

Fixed configurable cost for unused dustbin capacity.

Dustbins are extra source/destination positions whose costs use global features. They are not learned extra patch embeddings. Their capacities allow part of the local image and question mass to avoid direct local correspondence.

3. Specify both marginals

ρ = ot_dustbin_mass, 0 ≤ ρ < 1 aᵢ = (1 − ρ) / K for every image location a_dust = ρ bⱼ = Mⱼ · (1 − ρ) / Nᵦ for question position j b_dust = ρ sum(a) = sum(b) = 1

Local masses are uniform, rather than learned saliency weights. All valid question positions receive equal target mass. Padding and special positions have zero mass and receive exactly zero transport.

4. Solve the entropy-regularized constrained problem

minimize over P ≥ 0: Σᵢⱼ Pᵢⱼ Cᵢⱼ + ε Σᵢⱼ Pᵢⱼ (log Pᵢⱼ − 1) subject to: P · 1 = a, Pᵀ · 1 = b

The extended problem balances all mass. Its local-to-local block represents partial matching. Smaller ε usually favors more concentrated low-cost routes; larger values spread mass more broadly. These are soft alignments, not discrete object assignments.

Dustbin capacity is not a fixed discard percentage.

For exact marginals, let d = P[dust,dust]. Image-to-dustbin and dustbin-to-question mass each equal ρ − d; local matched mass equals 1 − 2ρ + d. Therefore max(0,1−2ρ) ≤ matched_mass ≤ 1−ρ. At the default ρ=0.2, local match mass lies between 0.6 and 0.8 of the total extended mass.

A larger bottom-right cost discourages dustbin-to-dustbin flow, all else equal, encouraging use of both cross-dustbin routes. At ρ=0, both dustbins carry zero mass and the method reduces to full balanced local OT. With finite Sinkhorn iterations, mass identities hold only approximately.

06 / Numerical engine

Sinkhorn scaling in log space

log_sinkhorn() checks shape compatibility, nonnegative marginals, matching total mass, positive epsilon/iteration count, and a positive row and column in every sample. It converts the cost and marginals to FP32, even when inputs use half precision.

log K = −C / ε repeat ot_iterations times: log uᵢ = log aᵢ − logsumexpⱼ(log Kᵢⱼ + log vⱼ) log vⱼ = log bⱼ − logsumexpᵢ(log Kᵢⱼ + log uᵢ) Pᵢⱼ = exp(log Kᵢⱼ + log uᵢ + log vⱼ)

Stable reductions

Log-sum-exp avoids directly scaling an extremely small exponential kernel. Each row update enforces source mass given the current column scaling, then each column update enforces destination mass.

Zero-mass masking

Invalid pairs initially use a finite −1e4 kernel sentinel. Invalid row/column dual variables are masked to −∞, and the final invalid plan entries are set to zero.

Fixed iterations

The code runs the configured number of iterations; there is no residual-based early stop. Twenty iterations are the default, not a guarantee of convergence. Inspect both marginal residuals.

The plan remains connected to PyTorch autograd. Cost and plan work scales roughly as O(B·K·L) per iteration, with cost construction also depending on width D. Training retains intermediate operations for backward propagation, so increasing iterations also increases training work and memory use.

07 / From alignment to memory

Ground each word with the evidence it receives

Take only the local block P_LL = P[:, :K, :L]. For question position j, sum incoming real-patch mass, normalize its weighted patch value, and calculate how much of its prescribed mass was supplied by local matches:

mⱼ = Σᵢ P_LL[i,j] alignedⱼ = (Σᵢ P_LL[i,j] · xᵢ) / max(mⱼ, 1e−8) gateⱼ = clamp(mⱼ / max(bⱼ, 1e−8), 0, 1) groundedⱼ = LayerNorm(qⱼ + gateⱼ · grounding_projection(alignedⱼ))

If most question mass is served by the image dustbin, the gate is small and less visual evidence is added. Real-patch evidence contributes more strongly when most of the token’s target mass is supplied by the local block. The clamp keeps gates in [0,1] even under approximate marginals.

global = LayerNorm(global_projection(concat(meanᵢ(xᵢ), gq))) memory = concat([global], grounded question positions) memory_blocked = concat([False], NOT content_mask)

Invalid question positions are explicitly zeroed after grounding and blocked from decoder cross-attention. The always-visible global token offers a second visual/text context route alongside local transport. Consequently, this model can use global image information even when local matches are weak.

The decoder memory is question-length, not patch-length.

It contains 1+L positions: a global token and the full padded question sequence. Raw image patches and dustbin positions do not become separate decoder memory tokens.

09 / Optimization and answer generation

Answer supervision trains the alignment

Training: reference prefixes

Answers are tokenized without automatic specials, truncated to A−2, wrapped with BOS/EOS, and padded to A. With MiniLM, CLS and SEP serve as BOS/EOS. The decoder sees ids[:, :-1] and predicts ids[:, 1:].

For “red”: [BOS, red, EOS, PAD] gives prefix [BOS, red, EOS] and targets [red, EOS, PAD]. Causal masking prevents reading future answer tokens; PAD targets do not contribute to loss.

Inference: generated prefixes

generate() encodes the image and question once, starts with BOS, and repeatedly takes the highest-logit next token. PAD and BOS cannot be selected. Finished samples get PAD while other samples continue.

Generation ends when all samples emit EOS or the length limit is reached. The returned IDs exclude the initial BOS. answers_from_ids() truncates at EOS and decodes while skipping special tokens.

The training loop

  1. Forward through OT and the decoder. Use reference-prefix embeddings, causal self-masks, and blocked-memory masks.
  2. Compute token cross-entropy. Training applies label smoothing (default 0.1). Validation uses unsmoothed cross-entropy. Both ignore the answer PAD ID.
  3. Backpropagate through memory and transport. Gradients reach projections and the question encoder through cost construction, Sinkhorn, aligned values, gates, and the global memory route. The image backbone remains frozen.
  4. Update trainable parameters. AdamW, default learning rate 1e−5, weight decay 0.05, gradient clipping at 1.0, and linear learning-rate decay with zero warmup.
  5. Score generated answers on train and validation splits. Rank 0 performs the full scoring passes after each epoch. Within each evaluated batch, loss and generation share one encoding.
  6. Save and select. Save last.pt every epoch and best.pt when validation loss decreases. Early stopping uses validation loss with default patience 8.
There is no separate OT loss in this implementation.

The entropic objective defines the plan inside fusion. The training objective is answer-token cross-entropy; the code does not add transport cost, contrastive retrieval loss, supervised patch matching, or a dustbin penalty to that loss.

generate() disables gradients, temporarily switches the model to evaluation mode, and restores its previous training state. Decoding recomputes attention over the whole growing prefix each step; this implementation has no KV cache or beam search.

11 / Data to checkpoint to answer

Run the OT pipeline

Run commands from the repository root. Dataset CSVs use image,question,answer and optionally anno_id. Paths are relative to the selected image root; --train_img_path, --dev_img_path, and --test_img_path can override split roots.

# Install the repository dependencies in your Python environment.
python -m pip install -r requirements.txt

# If needed, create the default GQA CSV/image subset.
python -m utils.download_gqa

# Explicitly select the optimal transport path.
python train.py --fusion ot --device auto \
  --train_csv_path data/gqa_dataset/train.csv \
  --dev_csv_path data/gqa_dataset/val.csv \
  --img_path data/gqa_dataset/images \
  --model_path data/gqa_ot \
  --ot_epsilon 0.05 --ot_iterations 20 \
  --ot_dustbin_mass 0.2 --ot_dustbin_cost 1.0

# Resume to a desired TOTAL of 20 epochs using saved model configuration.
python train.py --fusion ot --resume data/gqa_ot/last.pt \
  --model_path data/gqa_ot --epochs 20

# Evaluate generated answers on the held-out test CSV.
python test.py --fusion ot --checkpoint data/gqa_ot/best.pt \
  --split test --dataset gqa \
  --test_csv_path data/gqa_dataset/test.csv \
  --img_path data/gqa_dataset/images \
  --predictions_csv results/gqa_ot/test_predictions.csv \
  --report_json results/gqa_ot/test_report.json

# Generate an answer for one image.
python predict.py --checkpoint data/gqa_ot/best.pt \
  --image path/to/image.jpg --question "What color is the car?"

Image paths in the prediction command are placeholders. Downloading datasets and initially loading pretrained models requires network access. The downloaded GQA test CSV is a held-out subset of labeled validation data, not the official hidden-answer test split.

Answer metrics are separate from transport diagnostics

GQA

accuracy is binary exact match after trimming only leading/trailing whitespace. Case, punctuation, and internal whitespace still matter. It averages 0/1 per answer and does not give partial synonym credit.

PlantExpertVQA

Case-insensitive EM, SQuAD-style token F1, BLEU-1/2, ROUGE-L F1, and BERTScore F1. BERTScore defaults to bert-base-uncased, CPU, and English baseline rescaling. Rescaled scores can be negative.

--dataset auto detects GQA from the CSV path. Use an explicit dataset flag for custom paths. Performance reports measure VQA loss and generation time separately from answer scoring; CUDA peak memory is reported only for CUDA runs. Best checkpoint selection remains validation loss for either dataset.

Distributed training

torchrun --standalone --nnodes=1 --nproc_per_node=2 train.py --fusion ot --device cuda launches one worker per CUDA GPU. A distributed sampler partitions training, DDP synchronizes gradients, and rank 0 performs evaluation and writes artifacts. Batch size is per GPU. The single-device path also supports CPU and MPS.

What does high dustbin flow mean?

Local-to-global routes were favored under the current costs and capacity. This can reflect irrelevant content, poor representations, or the chosen hyperparameters. Inspect actual questions, residuals, and generated-answer quality before treating the flow as successful filtering.

What does low marginal residual prove?

It indicates that the numerical plan closely satisfies its mass constraints. It does not prove semantic alignment, use of the correct image region, or improved VQA quality.

What are the main architectural limits?

Local marginals are uniform; question tokenization may split a word into several equally weighted pieces. Cropping can remove visual evidence. Image features are frozen, and changing D does not fine-tune the image backbone. Fixed iteration counts can leave residuals. The global memory route can support answers without strong local grounding, so plan visualizations alone do not establish causal explanations.

15 / Formal methodology for the paper

Define the method independently of Python names

A paper should specify a mathematical mapping from an image and a question to an answer distribution. The following notation describes the current code, including affine biases, masking, finite iterations, and the global memory route. Batch indices are omitted for readability.

Problem definition and notation

Let a supervised dataset be 𝒟 = {(I⁽ⁿ⁾, Q⁽ⁿ⁾, Y⁽ⁿ⁾)}, where I is an RGB image, Q is an English question, and Y is an answer-token sequence terminated by EOS. The learning task is to estimate pθ(Y | I,Q). Reference answers affect training targets and prefixes; they do not enter the image–question transport costs.

F1. Feature representations

rᵢ = spatial_positionᵢ(Eimage(I)) ∈ ℝ^Ci e₁,…,eL = Equestion(tokenize(Q)), eⱼ ∈ ℝᵀ xᵢ = Wi rᵢ + bi, qⱼ = Wq eⱼ + bq x̄ = (1/K) Σᵢ xᵢ sQ = normalize(Σⱼ Aⱼ eⱼ / Σⱼ Aⱼ), q̄ = Wq sQ + bq

The last line is the default sentence-transformers path: Aⱼ is the tokenizer attention mask, which includes specials and excludes PAD; Mⱼ additionally excludes specials. Thus the global summary and local OT use different masks. Wi is replaced by identity when the image width equals D. For the supported alternative text path, the code substitutes the first contextual token for sQ.

F2. Extended cosine cost

normalize(v) = v / max(||v||₂, η), η = 10⁻¹² C̃ᵢⱼ = 1 − normalize(xᵢ)ᵀ normalize(qⱼ) C̃ᵢ∅ = 1 − normalize(xᵢ)ᵀ normalize(q̄) C̃∅ⱼ = 1 − normalize(x̄)ᵀ normalize(qⱼ) C̃∅∅ = c∅

The symbol ∅ identifies the added dustbin row or column. Cost computation uses FP32 copies, with the denominator floor from PyTorch’s documented normalize default. A dot product of normalized vectors determines compatibility, but the vectors used for aggregation keep their original magnitude. For unit normalized vectors, 1−cosine = ½ ||x̂−q̂||₂²; this is half the squared Euclidean distance. Vectors below the normalization floor are not unit vectors, so that identity does not apply to those degenerate cases.

F3. Marginals and coupling

a = [(1−ρ)/K,…,(1−ρ)/K, ρ] b = [M₁(1−ρ)/N,…,ML(1−ρ)/N, ρ] U(a,b) = {P ≥ 0 : P1 = a, Pᵀ1 = b} P* = argmin over P∈U(a,b) [ ⟨P,C̃⟩ + ε Σᵢⱼ Pᵢⱼ(log Pᵢⱼ−1) ] P⁽ˢ⁾ = LogSinkhorn(C̃,a,b; ε,S)

P* denotes the ideal converged solution; the network actually uses P⁽ˢ⁾. Interpret 0 log 0 as zero. Remove zero-mass rows/columns when discussing the positive-support problem. Keep them in implementation tensor shapes for batched masking.

F4. Local grounding and memory

mⱼ = Σᵢ₌₁ᴷ P⁽ˢ⁾ᵢⱼ zⱼ = Σᵢ₌₁ᴷ P⁽ˢ⁾ᵢⱼ xᵢ / max(mⱼ, δ), δ=10⁻⁸ γⱼ = clip(mⱼ / max(bⱼ,δ), 0,1) hⱼ = Mⱼ · LNtoken(qⱼ + γⱼ(Wg zⱼ + bg)) h₀ = LNglobal(W₀[x̄;q̄] + b₀) H = [h₀;h₁;…;hL], memory_blocked = [False; NOT M]

LNtoken and LNglobal are distinct learned LayerNorm modules. For invalid tokens, the implementation zeroes the normalized output and also blocks it. Both steps should be represented in the method, because having a zero vector alone does not prevent attention to that position.

F5. Autoregressive objective

pθ(Y | I,Q) = Πₜ pθ(yₜ | y<t,Hθ(I,Q)) πₜ = softmax(VocabularyHead(Decoder(H, AnswerEmbed(y<t)))) qtargetₜ(v) = (1−λ)·1[v=yₜ] + λ/V ℒtrain = −(1/Tvalid) Σₜ:yₜ≠PAD Σᵥ qtargetₜ(v) log πₜ(v)

Here λ=0.1 is the CLI training label-smoothing default, and Tvalid counts non-PAD targets including EOS. The loss shown is the minibatch reduction. Validation sets λ=0. Training logs average minibatch losses weighted by their non-PAD token counts. Do not confuse this λ with entropy ε or use the same symbol for both in the paper.

The vocabulary distribution includes the full vocabulary during training. Generation separately forbids selecting PAD and BOS. Thus greedy decoding has an additional token-selection constraint that is absent from the training softmax.

16 / Mathematical explanation

Derive what the constraints actually imply

The results below follow from the code’s marginals and memory equations. They explain the mechanism; they are not empirical statements about accuracy or new OT theorems.

1. Why Sinkhorn appears

On positive-mass support, introduce row and column multipliers f and g for the equality constraints. Differentiating the entropic Lagrangian with respect to an interior entry yields a factorized positive plan:

𝓛(P,f,g) = Σᵢⱼ PᵢⱼC̃ᵢⱼ + ε Σᵢⱼ Pᵢⱼ(log Pᵢⱼ−1) + Σᵢ fᵢ(aᵢ−ΣⱼPᵢⱼ) + Σⱼ gⱼ(bⱼ−ΣᵢPᵢⱼ) ∂𝓛/∂Pᵢⱼ = C̃ᵢⱼ + ε log Pᵢⱼ − fᵢ − gⱼ = 0 Pᵢⱼ = exp(fᵢ/ε) exp(−C̃ᵢⱼ/ε) exp(gⱼ/ε) P = diag(u) 𝒦 diag(v), 𝒦ᵢⱼ=exp(−C̃ᵢⱼ/ε) u ← a / (𝒦v), v ← b / (𝒦ᵀu)

Each division is elementwise. Taking logarithms gives the log-sum-exp updates in Section 6. The entropy term is strictly convex on positive entries; with finite costs, positive marginals on the reduced support, and ε>0, the ideal minimizer is unique. This does not make the whole neural training problem convex or guarantee that S iterations reach the minimizer. Entropic scaling is established methodology; cite Cuturi’s Sinkhorn paper for that foundation.

2. Dustbin capacity and the local matched fraction

Write the extended plan in blocks P=[R s; tᵀ d], where R couples real image and question positions, s routes real image mass to the question dustbin, t routes image-dustbin mass to real questions, and d couples dustbins.

Σᵢsᵢ + d = ρ, Σⱼtⱼ + d = ρ ΣᵢⱼRᵢⱼ + Σᵢsᵢ = 1−ρ Σᵢsᵢ = Σⱼtⱼ = ρ−d Mlocal = ΣᵢⱼRᵢⱼ = 1−2ρ+d max(0,2ρ−1) ≤ d ≤ ρ max(0,1−2ρ) ≤ Mlocal ≤ 1−ρ

The image and question unmatched-flow totals are equal under exact constraints even though their feature counts and individual costs differ. Local matching mass is determined by the optimized dustbin coupling as well as ρ. Both statements are approximate if row residuals remain nonzero.

Local retained fraction = Mlocal/(1−ρ) Local unmatched fraction = (ρ−d)/(1−ρ) At ρ=0.2: retained fraction ∈ [0.75,1]; unmatched fraction ∈ [0,0.25]

The earlier 0.6–0.8 bounds use total extended mass as denominator. The 0.75–1 bounds use real local mass as denominator. State the denominator whenever reporting “matched percentage” or “discarded percentage.” At ρ≥0.5, the lower bound permits zero local mass, although positive entropy and finite costs generally keep active support entries positive in the ideal solution.

3. Why the bottom-right cost changes matching

Consider a feasible two-by-two mass swap: add Δ to one local entry and to the dustbin-to-dustbin entry, and subtract Δ from that patch’s question-dustbin route and the image-dustbin route to that token. All row and column sums stay fixed.

Change in linear cost = Δ · (C̃ᵢⱼ + c∅ − C̃ᵢ∅ − C̃∅ⱼ) Direct local + dustbin pairing is cheaper when: C̃ᵢⱼ + c∅ < C̃ᵢ∅ + C̃∅ⱼ

This comparison explains a local preference in the linear part of the objective; it is not a hard rejection threshold. Entropy, other matches, and capacity compete globally. Raising c∅ penalizes retaining unused dustbin capacity, which can increase unmatched local flow. The parameter does not directly alter the prescribed dustbin mass.

4. The gate is a mass fraction, not a probability of correctness

For a valid token with exact marginals, bⱼ=mⱼ+tⱼ. Its gate is therefore γⱼ=1−tⱼ/bⱼ. It measures the fraction of prescribed token mass supplied by real image locations. It has no supervised confidence calibration or connection to answer correctness.

If mⱼ>δ and the gate is unclipped: γⱼ(Wg zⱼ + bg) = (Wg ΣᵢRᵢⱼxᵢ)/bⱼ + (mⱼ/bⱼ)bg

Without the grounding bias, normalized evidence plus the gate becomes a target-mass-normalized weighted sum. The code’s learned affine bias is also scaled by the gate. Near zero local mass, denominator clamping and gate clipping mean the exact algebraic simplification above no longer applies.

Because valid token marginals are uniform, the mean valid-token gate equals Mlocal/(1−ρ) when column marginals are exact and clamping is inactive. A mean gate and a matched-mass total contain closely related aggregate information; plotting both does not provide two independent demonstrations of grounding.

5. A useful control: constant costs

If every active entry of the extended matrix has the same cost, the entropy-maximizing feasible solution is P=abᵀ because both marginals total one. It depends only on the marginals:

Mlocal = (1−ρ)², d = ρ² Σᵢsᵢ = Σⱼtⱼ = ρ(1−ρ), γⱼ = 1−ρ At ρ=0.2: local=0.64, dustbin-to-dustbin=0.04, each cross flow=0.16

Nonzero dustbin flow can therefore occur without any semantic discrimination. This is why transport mass should be analyzed with feature-dependent cost patterns and answer behavior rather than described as evidence of filtering by itself.

6. Two distinct ways answer gradients reach image–question features

The training graph contains a value path and a routing path. The value path sends gradients through weighted visual aggregation and residual question features. The routing path sends gradients through gates, the finite Sinkhorn operations, cosine costs, and projected question/image features. Global summaries also influence both dustbin costs and the separate global memory token.

Routing: ℒ → decoder → H → {m,z,γ} → P⁽ˢ⁾ → C̃ → {x,q,x̄,q̄} Values: ℒ → decoder → H → {x,q,grounding/global projections} θimage_backbone: frozen; no parameter gradients θquestion_encoder, projections, decoder, head: trainable

This is unrolled differentiation through an approximate solver. The code neither differentiates implicitly through an exact optimum nor applies an envelope-theorem gradient of a standalone transport loss. Also, spatial locations are not assigned learned, question-dependent source marginal weights: task conditioning enters through the question features, globals, and pair costs.

The patch that sends more dustbin mass is not physically removed from the image tensor. Its remaining local mass still contributes to question grounding, and its feature still participates in the global image mean. Calling dustbins an “image region deletion” mechanism would misdescribe the implementation.

18 / Reproducible algorithm and resource analysis

Describe exactly what one forward pass computes

Algorithm 1: Question-conditioned partial-OT memory
Input: image I, question Q; frozen Eimage; trainable Equestion;
       projections; ρ, ε, c∅, S; decoder width D.
Output: memory H and blocked-memory mask.

1. Preprocess RGB image; extract spatial backbone features.
2. Project image features to D; remove ViT CLS if present.
3. Tokenize Q; encode contextual states; identify valid content tokens.
4. Reject samples with no valid content tokens.
5. Project token states and the encoder's global question summary.
6. Average projected spatial image values to obtain the image global.
7. Normalize FP32 copies and build the extended cosine cost C̃.
8. Set uniform real-token marginals and dustbin marginals ρ.
9. Initialize valid log-scalings to zero; invalid scalings to −∞.
10. Repeat S times: update row log-scaling; update column log-scaling.
11. Exponentiate the log-plan; set all invalid-pair entries to zero.
12. Extract the real-image / real-question block R.
13. For each token, compute incoming mass m, aligned value z, and gate γ.
14. Apply the gated visual residual and token LayerNorm.
15. Zero invalid grounded tokens.
16. Project concatenated global image/question values; global LayerNorm.
17. Concatenate global and grounded tokens; construct blocked mask.
Return H, mask; optionally return plan and mass/residual diagnostics.

Training then embeds the reference answer prefix, decodes with causal and memory masks, and computes the smoothed next-token loss. Inference reuses the same encoded memory at every greedy decoding step. OT is question-conditioned but not answer-prefix-conditioned: changing the generated answer prefix does not recompute the plan.

Complexity of the fusion stage

Leading costs per sample, excluding backbone encoders, answer decoder, and vocabulary projection.
OperationLeading timeExplanation
Image / question projectionsO(K·Ci·D + L·T·D)Image term vanishes as a learned projection when identity is used.
Cosine costsO(K·L·D)Pairwise local products dominate global dustbin products.
SinkhornO(S·(K+1)·(L+1))Two log-sum-exp reductions per iteration over padded support.
Weighted evidence aggregationO(K·L·D)Multiply the transposed local plan by spatial values.
Grounding / global projectionO(L·D² + D²)Dense token projection and a 2D-to-D global projection.

Storing the cost and final plan alone takes O((K+1)(L+1)) elements per sample. Ordinary unrolled autograd also retains solver intermediates across S iterations; actual training memory can grow with S and cannot be described by final-plan storage alone. Multiply tensor costs by batch size B and include encoder/decoder activations when reporting whole-model memory.

Without a KV cache, generation recomputes the growing answer prefix. Within each decoder layer, answer self-attention scales quadratically with prefix length and memory attention with prefix length times 1+L. The output projection also scales with vocabulary size. Fusion-only complexity is therefore not a complete estimate of end-to-end generation latency.

Implementation details the paper should state

Uniform local marginals; global-feature dustbins; fixed bottom-right cost; FP32 transport calculations; finite unrolled iterations; zero-mass PAD/special handling; preserved feature magnitudes in values; matched-mass gate; separate global memory token; causal answer decoding; pretrained frozen image backbone; separate answer embeddings; and checkpoint selection by unsmoothed validation token loss. Abstract draft, before results

Visual question answering requires associating question content with relevant visual evidence while handling incomplete local correspondence. We study a question-conditioned partial optimal transport fusion module for generative VQA. A frozen image encoder and a trainable question encoder produce spatial and contextual representations, which are projected into a shared feature space. Cosine costs, global-feature dustbins, and prescribed marginals define an entropy-regularized coupling estimated by finite log-space Sinkhorn iterations. The local coupling aggregates visual evidence for each content token, and its incoming matched mass controls a gated visual residual. A separate global memory token and the grounded question states condition autoregressive answer generation. Training uses answer-token cross-entropy without direct alignment labels. We define controlled comparisons with full OT and diagnostic analyses of transport mass, marginal residuals, and input reliance. The empirical benefits and computational tradeoffs must be determined through held-out evaluation.

After experiments, replace the final two sentences with the actual datasets/split sizes, primary metric changes, variability, and runtime tradeoff. Do not fill the abstract with planned improvements.

Method-section draft

Given an image I and a question Q, we construct decoder memory from spatial image features and contextual question tokens. Image features are projected to width D, and question states are mapped to the same width by a learned affine layer. Local matching excludes padding and special question tokens. The projected features remain unnormalized as values, while normalized FP32 copies define cosine matching costs.

We augment the local cost matrix with an image-dustbin row and a question-dustbin column. Their costs compare local values with the opposite modality’s global representation; the dustbin-to-dustbin cost is a fixed hyperparameter. Real image locations share mass 1−ρ uniformly, valid question tokens share the same mass uniformly, and each dustbin receives mass ρ. The resulting balanced extended problem permits partial local correspondence. We approximate its entropic optimum using S alternating log-space row and column scaling updates.

For each valid question token, the local coupling provides a normalized weighted average of spatial image values. The ratio of incoming real-patch mass to the token’s prescribed target mass scales a learned visual residual before token normalization. Padding and special-token memory positions are zeroed and blocked. We prepend a global token obtained from projected global image and question summaries, and use the resulting memory in a causal answer decoder. Model training minimizes smoothed next-token cross-entropy, propagating gradients through the finite transport iterations into the trainable question encoder and projections.
