How optimal transport drives this VQA model

A code-grounded tour from GQA image and question to an answer. The central operation is a differentiable, partial transport plan between ViT patches and BERT question tokens.

ViT patchesBERT tokensLog-domain SinkhornDustbin matchingAutoregressive decoder
01 · What the code does

One image, one question, one generated answer

The OT path keeps local visual and language features separate until it solves a constrained matching problem. The resulting plan weights the visual evidence delivered to each question token; a Transformer decoder then generates answer tokens.

INPUT

GQA-style row

image, question, answer, and optional anno_id. The dataset returns one answer for each row.

FUSION

Partial transport

Each image patch and valid question token receives prescribed mass. Global-feature dustbins absorb some unmatched content.

OUTPUT

Answer generation

Decoder cross-attention reads grounded question-token memory and produces a sequence from [CLS] to [SEP].

Evidence boundary

The source paper reports image-text retrieval results. This repository adapts its matching idea to VQA generation; a VQA accuracy gain still requires controlled SAN-versus-OT experiments.

  1. Load and validate rows

    load_dataframe checks required columns and normalizes whitespace. VQADataset resolves image paths and returns image tensors plus strings.

  2. Encode local features

    VQAModel.encode projects ViT features to d_model and sends patch tokens, BERT tokens, and the content-token mask to PartialTransportFusion.

  3. Align through OT

    The fusion module builds a cosine-cost matrix with dustbins, solves for a mass-constrained plan, and uses its local block to ground each valid question token.

  4. Decode an answer

    The decoder uses causal self-attention over answer tokens and cross-attention over OT memory. Padding memory positions are blocked.

04 · Core engine

Optimal partial transport, step by step

The code in model/optimal_transport.py performs the actual alignment. “Mass” is an abstract nonnegative weight; it is not a pixel count or a probability that an object exists.

1. Project values, normalize only for cost

The image projection has already produced patch vectors vᵢ ∈ Rᴰ. A learned linear layer maps BERT states to tⱼ ∈ Rᴰ. The code L2-normalizes FP32 copies to compute costs, while retaining the unnormalized vectors for decoder values.

Cᵢⱼ = 1 − cosine(vᵢ, tⱼ) = 1 − (vᵢ/‖vᵢ‖) · (tⱼ/‖tⱼ‖)

A low cost indicates high embedding similarity. The cost is approximately in [0,2]. For unit vectors, 1 − cosine equals half the squared Euclidean distance.

2. Add global-feature dustbins

The last column is a global question vector (projected BERT CLS): an image patch can send mass there. The last row is the mean image-patch vector: a question token can receive mass from it. Each cross-dustbin cost is again 1 − cosine. The bottom-right dustbin-to-dustbin cost is a configurable constant, default 1.0.

3. Prescribe row and column mass

With ρ = --ot_dustbin_mass, all valid patches share 1−ρ equally, all valid content tokens share 1−ρ equally, and each dustbin has mass ρ. Padded or special question tokens have zero column mass.

αᵢ = (1−ρ)/K for each patch; αdust = ρ
βⱼ = (1−ρ)/N for each valid token; βinvalid = 0; βdust = ρ
Σᵢ αᵢ = Σⱼ βⱼ = 1

The solver seeks a nonnegative plan P whose row sums approximate α and column sums approximate β, while preferring low-cost matches. This is an extended balanced transport problem: partial local matching is represented by the dustbin row and column.

What ρ=0.2 actually means

It is 20% capacity on each dustbin, not a guarantee that exactly 20% of local content is discarded. If d=P[dust,dust], then local-to-local mass is 1−2ρ+d; image-to-dustbin and dustbin-to-question mass each equal ρ−d when marginals are exact. At ρ=0.2, local match mass can lie between 0.6 and 0.8.

4. Solve entropic OT

P* = argminP≥0; P1=α; Pᵀ1=β ⟨P,C⟩ − ε H(P)
H(P) = −Σᵢⱼ Pᵢⱼ(log Pᵢⱼ − 1)

The entropy term makes the plan smoother and enables Sinkhorn scaling. The code default is ε=0.05 and 20 iterations. These are repository defaults to tune on GQA validation data, not the paper’s selected VQA settings.

05 · Numerical method

How log-domain Sinkhorn is implemented

The separate log_sinkhorn function checks shapes, nonnegative marginals, and equal total row/column mass. It casts the cost and marginals to FP32 before solving, even if model values came from half precision.

logK = −C / ε
logu = log α − logsumexp(logK + logv, columns)
logv = log β − logsumexp(logK + logu, rows)
P    = exp(logK + logu + logv)

It alternates the two updates for the requested iteration count. Invalid rows and columns have zero marginal; their pair costs are masked and their dual variables become −∞. The final plan explicitly zeros those entries. This avoids matching PAD, CLS, or SEP positions.

WHY LOG SPACE?

Numerical range

Directly exponentiating −C/ε can underflow for small ε. Log-sum-exp scaling handles tiny kernel values more safely.

CONVERGENCE

Finite iteration result

Twenty iterations do not mathematically guarantee exact marginals. The code reports maximum row and column residuals so the approximation can be checked.

Approximate solver work scales as O(B·(K+1)·(L+1)·iterations); the plan itself stores O(B·(K+1)·(L+1)) values. Autograd through the iterations adds training memory.

07 · OT to language generation

The plan becomes decoder memory

The decoder does not receive the full transport matrix as attention weights. The code first extracts only the local-to-local block PLL, excluding every dustbin interaction from patch alignment.

mⱼ = Σᵢ Pᵢⱼ   (local patch mass for token j)
aⱼ = (Σᵢ Pᵢⱼ vᵢ) / max(mⱼ, 10⁻⁸)
gⱼ = clamp(mⱼ / βⱼ, 0, 1)
memoryⱼ = LayerNorm(tⱼ + gⱼ · Wgroundaⱼ)

aⱼ is a weighted patch value for token j. gⱼ is the fraction of that token’s assigned mass supplied by real patches. A token mostly served by the image dustbin gets a small visual contribution. Invalid token memory is zeroed and masked from decoder cross-attention.

A separate global memory token is LayerNorm(Wglobal[mean(image patches); projected BERT CLS]). It remains available even when individual local matches are weak. The final memory length is 1+L.

Interpret the plan carefully

High transport mass means the learned embedding cost and marginal constraints favored a pairing. It is useful for diagnosis, but it is not proof of causal grounding or a calibrated explanation of the answer.

08 · Optimization and use

Training, validation, and inference

TRAIN

Teacher-forced cross-entropy

train.py shifts answer IDs by one position, ignores PAD in the loss, applies label smoothing, and updates trainable modules with AdamW. The ViT stays frozen; the BERT question encoder, projections, OT fusion, decoder, and output head can learn. Answer embeddings are frozen by default in the CLI.

SELECT

Validation loss

After each epoch, evaluation computes EM, Token-F1, BLEU-1/2, ROUGE-L, and BERTScore-F1. The lowest validation loss selects best.pt. The run also saves last.pt, metrics, a plot, and a configuration manifest.

At inference, generation starts with [CLS], repeatedly chooses the highest-logit next token, and stops at [SEP] or the maximum length.

Run commands

python train.py --fusion ot --device cuda --train_csv_path data/gqa_dataset/train.csv --dev_csv_path data/gqa_dataset/val.csv --img_path data/gqa_dataset/images --model_path data/gqa_model
python test.py --checkpoint data/gqa_model/best.pt --split dev --device cuda
python predict.py --checkpoint data/gqa_model/best.pt --image path/to/image.jpg --question "What color is the car?" --device cuda

--device cuda requires a CUDA-enabled PyTorch installation. New runs default to OT; the explicit flag makes the architecture clear. Use --fusion san and a separate output path for the baseline. The code also accepts existing CSV/image layouts through path flags.

10 · Research adaptation

What comes from the paper, and what changes here

The reference is Pan et al., Learning Image-Text Matching with Optimal Partial Transport (OMIT, arXiv v1). The local copy is 2603.14349v1.pdf. Its Section 3 introduces local image/text cost, entropic OT, global-feature dustbins, and local-match-only similarity.

ConceptOMIT paperThis repository
TaskRank matching image-caption pairs for retrieval.Generate a short answer conditioned on an image and question.
Local featuresVisual regions/grid features and caption fragments, with multiple encoder settings.Frozen ViT patch states and contextual BERT question states.
Transport outputUse local matched mass to compute an image-text similarity score.Use local matched mass to build grounded decoder memory.
Training objectiveRetrieval ranking/contrastive learning with negatives.Teacher-forced answer-token cross-entropy; no retrieval ranking loss.
SettingsPaper reports its own retrieval settings, including entropy λ=0.02.VQA defaults ε=0.05, 20 iterations, ρ=0.2, dustbin-to-dustbin cost=1.0; validate these on GQA.

The paper’s retrieval results do not establish GQA performance. Its qualitative appendix also reports difficulty with relational words and distinguishing entities; these are relevant risks for VQA.

11 · Checking behavior

What to measure before claiming improvement

TRANSPORT HEALTH

Plan and solver

diagnose_training.py averages local matched mass and the three dustbin flows, and records maximum marginal residuals. Inspect these values by question type as well as overall.

VQA QUALITY

Generated answers

test.py reports EM, Token-F1, BLEU-1/2, ROUGE-L, BERTScore-F1, throughput, latency, and peak CUDA memory. compare_predictions.py pairs SAN and OT outputs by anno_id and bootstraps score differences for all six metrics.

What does a large dustbin flow imply?

The learned costs favor leaving more patch/token mass unmatched within the allowed capacity. It may reflect irrelevant regions, weak embeddings, or poor hyperparameters. Compare answer accuracy and examples before interpreting it as useful filtering.

Why can a low residual still produce a bad answer?

Residuals measure whether the transport constraints were approximately met. They do not measure whether costs capture the right semantics, whether visual features resolve objects/relations, or whether the decoder uses the image.

How can image reliance be checked?

The diagnostics script generates answers after shuffling images or questions within a small batch. If predictions barely change when images change, the model may be relying mainly on question or answer priors.

Current scope

The repository contains implementation and tests, but this guide does not claim a measured GQA accuracy gain. Compare the same held-out examples and matched training settings, and keep the final test split separate from tuning.
